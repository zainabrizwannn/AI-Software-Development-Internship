# Week 6 Part B - Advanced Retrieval

## Challenge 1 - Plain Retriever vs MultiQueryRetriever

The same five test questions were run against:

1. Plain Chroma Retriever
2. MultiQueryRetriever

Verbose logging was enabled so the reformulated queries generated by MultiQueryRetriever could be inspected.

---

### Test Question 1

Question:

`Which book is about data structures and algorithms?`

Plain Retriever results:

- DSA.txt
- The Pragmatic Programmer.txt
- Clean Code.txt

MultiQueryRetriever results:

- DSA.txt
- The Pragmatic Programmer.txt
- Clean Code.txt
- Software Engineering.txt

Generated reformulated queries included:

- What are the top-recommended textbooks for learning computer science algorithms and data structures?
- Can you suggest reading materials that cover fundamental data organization and algorithm design?
- Which popular books focus on teaching algorithms and data structures to programmers?

Result:

The two retrievers disagreed.

MultiQueryRetriever added:

`Software Engineering.txt`

Explanation:

The generated queries used broader terms such as computer science, programming, and reading materials. This caused the retriever to also find Software Engineering.

The extra result did not significantly improve this specific search because the original question was specifically about data structures and algorithms, and DSA.txt was already correctly retrieved by the plain retriever.

## Challenge 1 Conclusion

The plain retriever performs retrieval using only the user's original question.

MultiQueryRetriever generates several alternative versions of the question and performs retrieval for each version.

In this test:

- Question 1 returned one additional source with MultiQueryRetriever.
- Questions 2 and 3 returned the same sources.
- Question 4 showed the clearest improvement in recall because MultiQueryRetriever retrieved two additional library books.
- Question 5 returned the same sources.

The test shows that MultiQueryRetriever can improve recall when alternative wording matches documents that the original query does not retrieve.

However, generating broader queries can also retrieve less-specific documents, as seen in Question 1.

## Challenge 2 - When MultiQueryRetriever Makes Retrieval Worse

Test question:

`I specifically want the book about data structures and algorithms. Which book matches that topic?`

### Plain Retriever Results

The plain retriever returned:

- DSA.txt
- The Pragmatic Programmer.txt
- Software Engineering.txt

### MultiQueryRetriever Results

The MultiQueryRetriever returned:

- DSA.txt
- The Pragmatic Programmer.txt
- The Alchemist.txt
- Software Engineering.txt

### Generated Queries

MultiQueryRetriever generated alternative versions of the question such as:

- Which specific book focuses on teaching data structures and algorithms?
- What is the title of the textbook that covers data structures and algorithm design?
- Can you identify the book in the database that deals with computer science algorithms and data structures?

### Worse Result

The extra document returned only by MultiQueryRetriever was:

`The Alchemist.txt`

This document is unrelated to data structures and algorithms.

The plain retriever did not return this irrelevant document.

Therefore, in this test, MultiQueryRetriever made retrieval worse by reducing precision.

### Trade-off

MultiQueryRetriever improves recall by generating multiple alternative versions of the user's question and searching for each one.

This can help retrieve relevant documents that a single query might miss.

However, because it searches using several generated queries, it may also retrieve documents that are only loosely related or completely irrelevant.

This creates a trade-off:

- Plain retrieval may have better precision but can miss relevant documents.
- MultiQueryRetriever can improve recall but may reduce precision by introducing irrelevant documents.

In this example, the additional query variations caused `The Alchemist.txt` to be retrieved even though it was not relevant to the requested topic.

Therefore, MultiQueryRetriever is useful when improving recall is important, but its results may require filtering or re-ranking to maintain high precision.
